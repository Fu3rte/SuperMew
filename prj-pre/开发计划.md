# 开发计划（RagProof）

> 项目名：RagProof（知鉴）｜基线：开源项目 SuperMew（MIT）
> 配套文档：`PRD.md`（需求）、`backend-agent-project-resume-pack.md`（简历规格）、`candidate-pool.md`（调研）
> 策略：**C — fork 开源基线 + 自研独立增量**
> 目标：7 天内跑通 MVP 闭环，并产出 2 个真正属于自己、可演示、可讲清的自研功能
> 更新：2026-09-09

---

## 1. 策略与原则

**基线**：fork `icey1287/SuperMew`（MIT），保留 upstream 作为对照。
**自研增量**：只做 PRD 里上游没有的部分，放独立目录/分支，用 `git diff upstream/main` 作为贡献清单。
**三条铁律**：

1. **先加法，后改造**：P4 之前不碰 upstream 核心状态模型。
2. **改了 RAG 相关逻辑，必须同步加评测用例或门禁指标**——否则破坏"评测治理"主线。
3. **每个 FR 留一份可演示证据**（命令输出 / 报告 / 失败 case 列表 / 测试结果），没有证据不写进简历。

## 2. 仓库与分支工作流

```bash
# 1. GitHub 网页 fork icey1287/SuperMew → <你>/SuperMew
git clone https://github.com/<你>/SuperMew.git
cd SuperMew

# 2. 加 upstream 用于对照/同步
git remote add upstream https://github.com/icey1287/SuperMew.git
git remote -v

# 3. 每个 FR 一条分支
git checkout -b feat/fr9-failure-attribution
```

## 5. 分阶段计划

### P0 · 环境与离线评测（0.5 天）
- 动作：`uv sync`；`docker compose up`；跑 `scripts/evaluate_rag.py validate` + `score`（用离线 Observation，**无需模型/Milvus**）。
- 验收证据：门禁 PASS/FAIL 输出；`evals/rag/baseline_v1.json` 可重建。
- 对应 FR：FR-4 / FR-5 / FR-6。


### P1 · 复现一次回归被卡（1 天）
- 动作：读 `backend/rag/pipeline.py` + `backend/evaluation/rag.py`；手改一条 Observation 或 gate 阈值，复现 FAILED。
- 验收证据：回退报告 + 被点名的 case 列表；能说清 `_evaluate_gates` 判定逻辑。
- 对应 FR：FR-2 / FR-6。

### P2 · 评测任务与收敛（1 天）
- 动作：跑一次持久化评测 Job；kill worker 验证任务状态收敛、旧 worker 无法写入。
- 验收证据：租约/心跳日志；`fencing_token` 失配被拒的记录。
- 对应 FR：FR-5。

### P3 · 流水线门禁（1 天）
- 动作：把离线门禁接进自己 fork 的 CI；人为制造回退，确认流水线被卡。
- 验收证据：CI 失败记录 + 报告 artifact。
- 对应 FR：FR-8。

### P4 · 自研增量（1–2 天）★核心
- **FR-9 失败归因**：新建 `backend/evaluation/reporting/attribution.py`，从已有 case 结果按超时 / 指标不达标 / 调用失败 / 缺证分类聚合，挂到报告渲染。
- **FR-10 Holdout 对比**：扩展 `scripts/evaluate_rag.py` 与报告渲染，支持开发集 vs Holdout 指标对比导出。
- 验收证据：一份带失败归因的报告 + 一份 Holdout 对比报告；对应单测；`git diff upstream/main`。
- 对应 FR：FR-9 / FR-10。

### P5 · 收尾（1 天）
- 动作：整理 demo 路径、README 贡献说明、简历条目定稿与自检。
- 验收证据：一条可复现的端到端演示命令；简历条目逐条能追到实现细节。

### V1（后续，可选）
- FR-11：语料/索引更新触发重测 + 漂移告警（`backend/workers/` + 调度）。
- FR-13：角色权限 + 操作记录（需动 schema/权限模型）。

### V2（后续，高风险）
- FR-12：`backend/rag/pipeline.py` 状态模型 + `ModelRole` + DB 迁移 + 前端 + **同步扩 `evals/rag` 用例/指标/门禁**。
- 分步：S1 verify/critic → S2 planner → S3 预算账本 + 重试 → S4 控制面 → S5 评测扩展。

| FR | 落点 | 验收方式 |

## 7. 风险与回退

| 风险 | 应对 |
| --- | --- |
| 环境跑不通（模型/Milvus） | 先用离线评测（`contract_smoke`），零外部依赖 |
| 时间不够 | 砍序：FR-12 → FR-13 → FR-11 → FR-8；**保底 P0–P2 + P4** |
| 自研功能破坏主链路 | 放独立目录/分支，跑完整评测回归 |
| 与上游混淆 | 保留 upstream remote，`git diff upstream/main` 作贡献清单 |
| 多步骤改造失控 | 后置 V2，先扩评测再改状态模型 |
